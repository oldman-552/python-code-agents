# RCTFC PDTM Auditor 2.2

أداة سطر أوامر لعمل **جرد لأدوات ProjectDiscovery المُدارة عبر PDTM** وتشغيل مجموعة صغيرة من الفحوص المصرّح بها فقط. لا تُثبّت الأدوات تلقائيًا، ولا تشغّل `pdtm -install-all`، ولا تدّعي تغطية كل فئات اختبار الاختراق.

## ما الذي يعمل؟

- يقرأ أدوات PDTM المعروفة من `~/.pdtm/go/bin` و`PATH`، ويفحص ترويسة الملف التنفيذي لتجنب الخلط بأوامر Python ذات الاسم نفسه؛ لا يعدّ هذا تحققًا تشفيريًا من هوية الناشر. ويعرض الملفات التنفيذية غير المعروفة في مجلد PDTM دون تشغيلها.
- يرفض بدء أي عملية فحص قبل التحقق من **كل** الأهداف مقابل `--scope` ووجود `--authorization-ref`.
- إذا لم يُمرّر `--mode` في جلسة طرفية، يسأل المستخدم أولًا `passive` أم `active`. في التشغيل غير التفاعلي يجب تمرير `--mode` صراحة.
- `passive`: لا يرسل طلبات مباشرة إلى الهدف. يمكن تشغيل `subfinder` فقط مع `--allow-third-party-sources`، وهو خيار يقرّ بأن الاستعلامات ستصل إلى مصادر خارجية.
- `active`: يشغّل `dnsx` و`httpx` و`tlsx` عند توفرها، على الأهداف المحددة صراحةً والمطابقة للنطاق فقط، بمعدل/مهلة محدودين. لا تتحول نتائج `subfinder` تلقائيًا إلى أهداف نشطة حتى إن كانت داخل wildcard؛ راجعها ثم أضف ما يلزم إلى طلب جديد صريح. `dnsx` يتصل بمحللات DNS؛ وعدد طلبات الأدوات الداخلي غير قابل للعد بدقة عبر واجهة موحدة.
- `naabu` اختياري منفصل عبر `--enable-port-scan`، ومحدود بالمنافذ `80,443,8080,8443`. لا يُشغّل على أسماء نطاقات لتجنب فحص عناوين CDN مشتركة؛ يلزم هدف IP حرفي داخل النطاق.
- يرصد مؤشرات حقن التعليمات في النصوص التي تُرجعها الأدوات، ويعاملها كبيانات غير موثوقة لا تغيّر النطاق أو الخطة. يُحلّل JSONL الخاص بـ`httpx` فقط إذا كان URL الذي أبلغت عنه الأداة يطابق هدفًا محددًا ومصرّحًا به. تُطبّع أسماء الرؤوس التي يخرجها `httpx` بصيغة snake_case، وتُؤجّل ملاحظات الرؤوس الدفاعية عند استجابة إعادة توجيه 3xx إلى أن يُفحص عنوان الوجهة صراحةً وضمن النطاق.
- يعلن نوع/موضع القيم التي تشبه الأسرار ويقنّع قيمتها، مع إبقاء JSON/JSONL صالحًا حيث أمكن. تُشغّل العمليات بلا shell، ببيئة متغيرات مصغرة ومجلد `HOME` مؤقت معزول؛ لا ترث مفاتيح API أو إعدادات proxy من بيئة المشغّل.
- يكتب غلاف JSON v2.2 إلى stdout وسجلات إلى stderr، إضافةً إلى `report.json`, `report.jsonl`, `findings.csv`, و`recommendations.md` داخل `out/<run_id>/`.

## ما الذي لا يشغّله تلقائيًا؟

الأداة تعرض القرار وسببه لكل أداة معروفة؛ «لم تُشغّل» لا تعني «اجتازت الاختبار». لا تشغّل تلقائيًا `nuclei` أو `katana` أو `shuffledns` أو `interactsh-client` أو أدوات الإشعارات/السحابة/البحث الخارجي، لأن القوالب والزحف وتعداد القوة الغاشمة والاتصالات الخارجية قد توسّع النطاق أو تولّد أثرًا جانبيًا. كما تُسجّل الأدوات المثبتة غير المعروفة ولا تشغّلها. قائمة PDTM تتغير؛ لذا يجب مراجعة `tool_inventory` و`unclassified_pdtm_executables` في كل تقرير.

هذا **ليس بديلًا عن اختبار اختراق شامل**: لا يوجد اختبار مصادقة، ولا اختبار منطق أعمال، ولا مراجعة مصدر، ولا إثبات استغلال، ولا فحص شامل لكل منافذ/مسارات/قوالب. لا يمكن ضمان أن «كل شيء» قد اكتُشف.

## التثبيت

المتطلبات: Python 3.11+، و`pdtm` وأي أدوات تريد تشغيلها مثبتة مسبقًا. التثبيت يدوي فقط؛ راجع [المشروع الرسمي لـ PDTM](https://github.com/projectdiscovery/pdtm). مثال تثبيت مجموعة صغيرة بعد مراجعة الأداة:

```bash
pdtm -install httpx,dnsx,tlsx
```

لا يحتاج البرنامج إلى حزم Python خارج المكتبة القياسية. `pytest` مطلوب فقط لتشغيل الاختبارات الموجودة في المشروع.

## تشغيل تفاعلي

```bash
python rctfc_template.py \
  --target https://www.example.com/ \
  --scope example.com \
  --authorization-ref AUTH-2026-001
```

سيطلب اختيار `passive` أو `active` قبل بدء أي عملية شبكة. النطاق العاري `example.com` يطابق المضيف نفسه فقط. استخدم `*.example.com` للسماح بالنطاقات الفرعية؛ لا يشمل هذا النمط النطاق الأساسي نفسه. مرجع التفويض هو إقرار نصي من المشغّل، ولا تتحقق الأداة منه مستقلًا.

تشغيل غير تفاعلي:

```bash
python rctfc_template.py \
  --target https://www.example.com/ \
  --scope example.com \
  --authorization-ref AUTH-2026-001 \
  --mode active \
  --rate 1 \
  --timeout 15 \
  --out out
```

لتمكين مصادر الاستطلاع الخارجية صراحةً في الوضع السلبي (أو أثناء الوضع النشط):

```bash
python rctfc_template.py \
  --target https://www.example.com/ \
  --scope '*.example.com' \
  --authorization-ref AUTH-2026-001 \
  --mode passive \
  --allow-third-party-sources
```

فحص المنافذ اختياري ويحتاج عنوان IP داخل النطاق:

```bash
python rctfc_template.py \
  --target 203.0.113.10 \
  --scope 203.0.113.10/32 \
  --authorization-ref AUTH-2026-001 \
  --mode active \
  --enable-port-scan
```

`203.0.113.10` عنوان توثيقي فقط وليس هدفًا حقيقيًا.

## ملف JSON

```json
{
  "request_id": "req-001",
  "operation": "scan",
  "input": {
    "target": ["https://www.example.com/"],
    "scope": ["example.com"]
  },
  "options": {
    "mode": "active",
    "rate_limit_rps": 1,
    "timeout_s": 15,
    "max_sample_items": 3,
    "out_dir": "out"
  },
  "metadata": {
    "authorization_ref": "AUTH-2026-001"
  }
}
```

```bash
python rctfc_template.py --config request.json
```

يُقبل JSON من stdin عند تمرير بيانات إليه. ترتيب الدمج: defaults → config → stdin JSON → `RCTFC_*` environment → CLI. أسماء الحقول في JSON مطابقة للمخطط أعلاه؛ لا تُقبل المرادفات.

## حالات التشغيل وأكواد الخروج

- `ok`: كل الأدوات المختارة المتاحة انتهت دون خطأ، ولا تعني أن الهدف آمن.
- `partial`: أدوات غير مثبتة أو مستبعدة عمدًا أو إخفاقات تنفيذية؛ راجع القائمة كاملة.
- `refused`: هدف خارج النطاق؛ لم يبدأ أي برنامج فحص، وكود الخروج `3`.
- `error`: مدخلات غير صالحة (`2`) أو خطأ تشغيل (`1`).
- كود `10`: نتيجة بلغت عتبة `--fail-on` عندما اكتمل التشغيل بحالة `ok`.

في عمليات الفحص تكون `metrics.requests_sent` بقيمة `null` لأن العدد الفعلي الذي ترسله الأدوات الخارجية غير معروف؛ الغلاف نفسه لا يرسل الطلبات. يُذكر ذلك صراحةً في `data.coverage.external_tool_request_count` بدل اختلاق رقم. في الجرد المحلي أو الرفض قبل بدء الفحص يكون العدد `0`. يحد `max_sample_items` عناصر المصفوفات المساعدة تحت `data.samples` فقط؛ المخرجات الكاملة المنقحة تبقى في `data.tool_results`، وتظهر أعداد ما لم يُعرض في `omitted_counts`.

## حدود حماية البيانات

- لا تحفظ الأداة أجسام استجابات HTTP؛ يطلب `httpx` حذف جسم الاستجابة من مخرجاته. لذلك لا تُفحص تعليمات الحقن أو الأسرار داخل متن صفحات الويب، ولا يجوز اعتبار غياب إنذار دليلًا على خلو المتن منها.
- تُنقّح مخرجات الأدوات قبل وضعها في التقرير. عند اكتشاف سر محتمل تُعلن الأداة النوع والموقع وتخفي القيمة الحرفية.
- لا تمرر بيانات اعتماد أو أسرار داخل عنوان URL. يرفض هذا الملف عناوين الأهداف التي تحتوي على query string كليًا لتقليل خطر أسرار URL أو نقاط GET ذات الأثر الجانبي، ولا ينفّذ اختبارات مصادقة.
- لا تُرسل نتائج إلى `notify` أو أي وجهة خارجية، ولا تثبّت أو تحدّث أدوات تلقائيًا.
- مخرجات الأدوات غير موثوقة؛ لا تتحكم في النطاق أو خطة التشغيل.
